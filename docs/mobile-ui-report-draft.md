# 모바일 UI 보고서 작성본
작성 범위: 본 문서는 현재 모바일 클라이언트에 구현된 UI를 보고서 형태로 정리한 내용이다. 실제 코드 전문은 제외하고, 화면 목적, 구성 요소, 사용자 흐름, 설계 의도를 중심으로 서술하였다. 기준 시점은 2026년 6월 3일이며, 숨김 처리된 Expo 기본 예제 화면인 `explore` 탭은 설명 대상에서 제외하였다.

## 1. 배경 지식

### 가. React Native와 Expo 기반 구성
본 프로젝트의 모바일 UI는 React Native와 Expo 기반으로 구현되어 있다. 이 조합은 하나의 코드베이스로 안드로이드 중심의 앱 화면을 빠르게 구성할 수 있고, 네이티브 기능과 화면 단위 컴포넌트를 효율적으로 결합할 수 있다는 장점이 있다. 현재 앱은 로그인, 대시보드, 댄스 클래스 탐색, 음식 분석, 기록 조회, 프로필 관리처럼 성격이 다른 화면을 함께 포함하고 있기 때문에, 화면 재사용성과 상태 전환이 자연스러운 구조가 중요하다.

또한 본 프로젝트는 단순 정보 조회형 앱이 아니라 카메라 촬영, 이미지 업로드, 실시간 댄스 연습, 분석 결과 확인까지 포함한 상호작용형 앱이다. 따라서 각 화면은 시각적으로 화려한 느낌을 유지하면서도, 버튼 위치와 상태 변화가 명확하게 보이도록 설계되어 있다.

### 나. Expo Router와 하단 탭 내비게이션
앱의 주요 이동 구조는 Expo Router 기반의 파일 라우팅과 하단 탭 내비게이션으로 구성되어 있다. 로그인 이후 사용자는 홈, 클래스, 음식, 기록, 프로필의 5개 핵심 영역을 하단 탭에서 바로 이동할 수 있다. 이 구조는 사용자가 자주 오가는 화면을 고정된 위치에 배치해 탐색 비용을 줄이고, 기능이 많아져도 전체 구조를 쉽게 이해할 수 있도록 돕는다.

하단 탭은 기본 시스템 탭을 그대로 사용하지 않고, 별도의 커스텀 탭 바를 적용해 활성 탭 강조점과 아이콘 상태를 앱 전체 디자인 톤에 맞추었다. 이를 통해 화면 전환 구조 역시 UI의 일부로 통합되도록 구성하였다.

### 다. Vision Camera와 Image Picker 활용
음식 분석 화면은 카메라 촬영과 갤러리 선택 흐름을 모두 지원하고, 댄스 연습 화면은 실시간 카메라 프레임을 기반으로 동작한다. 이를 위해 이미지 입력에는 Expo Image Picker를 사용하고, 실시간 댄스 연습에는 Vision Camera를 사용한다. 이와 같은 구성은 사용자가 입력을 준비하는 단계와 실제 분석이 진행되는 단계를 명확히 분리하면서도, 모바일 환경에 익숙한 방식으로 기능을 수행할 수 있게 한다.

## 2. UI 설계 개요

### 가. 전체 화면 구조
앱의 첫 진입 구간은 로그인 화면과 회원가입 화면이다. 인증이 완료되면 사용자는 메인 탭 구조로 진입하며, 이후 모든 핵심 기능은 하단 탭을 통해 접근한다. 홈 화면은 오늘의 상태와 추천 클래스를 보여주는 대시보드 역할을 수행하고, 클래스 화면은 운동 콘텐츠를 탐색하고 선택하는 역할을 맡는다. 음식 화면은 식단 이미지를 분석하는 입력 중심 화면이며, 기록 화면은 운동 및 체형 변화 기록을 시각화해 보여준다. 프로필 화면은 신체 정보와 목표, 누적 성과를 관리하는 개인 설정 공간이다.

이 구조는 사용자의 실제 루틴 흐름을 반영한다. 즉 사용자는 앱에 로그인한 뒤 현재 상태를 확인하고, 필요한 운동을 찾고, 연습을 수행한 다음, 식단과 기록을 확인하고, 마지막으로 프로필과 목표를 점검하는 흐름으로 앱을 이용할 수 있다.

### 나. 공통 시각 언어
앱 전반은 어두운 배경을 중심으로 하는 다크 테마 UI를 사용한다. 기본 배경은 거의 검정에 가까운 짙은 톤으로 구성하고, 카드 영역은 한 단계 밝은 회색 계열로 구분하였다. 주요 강조색은 핑크 계열, 오렌지 계열, 보라 계열, 틸 계열을 함께 사용하여 기능 성격에 따라 시선을 분산시키지 않으면서도 상태 구분이 가능하도록 설계하였다.

버튼, 카드, 모달, 통계 칩 등 대부분의 요소는 둥근 모서리와 여백이 넉넉한 카드형 구조를 따른다. 이는 운동, 기록, 분석 결과처럼 서로 다른 정보 단위를 명확히 분리해 보여주는 데 유리하다. 또한 아이콘을 적극적으로 병행해 텍스트만으로는 바로 인지하기 어려운 기능 목적을 빠르게 전달하도록 구성하였다.

### 다. 상호작용 방식
이 앱의 UI는 정적인 정보 표시보다 "다음 행동을 유도하는 구조"에 초점을 둔다. 홈에서는 추천 클래스로 바로 이동할 수 있고, 클래스 화면에서는 상세 모달과 연습 모달로 이어지며, 음식 화면에서는 촬영 후 바로 분석 버튼으로 이어진다. 기록과 프로필 화면은 사용자가 자신의 변화와 누적 결과를 다시 확인하도록 유도하는 피드백 성격이 강하다.

또한 상세 정보는 전부 새로운 페이지로 분기하지 않고, 바텀 시트형 모달과 전체 화면형 연습 모달을 함께 사용해 흐름을 끊지 않도록 구성하였다. 이는 콘텐츠 탐색과 실행을 한 화면 체계 안에서 연결하기 위한 설계이다.

## 3. 화면별 구현 내용

### 가. 로그인 화면
로그인 화면은 이메일과 비밀번호를 입력받아 인증을 수행하는 기본 진입 화면이다. 상단에는 간단한 환영 배지와 큰 제목을 배치해 첫 인상을 만들고, 그 아래 카드형 입력 영역을 배치해 실제 행동 영역을 분리하였다. 입력 칸에는 메일, 자물쇠 아이콘을 넣어 입력 목적을 즉시 인지할 수 있도록 하였으며, 비밀번호는 보기/숨기기 전환 버튼을 제공한다.

오류가 발생했을 경우에는 입력 카드 안에서 즉시 확인 가능한 에러 박스를 표시하고, 로그인 버튼은 요청 중 비활성화 상태와 진행 문구를 보여준다. 하단에는 구글 로그인 버튼과 회원가입 화면으로 이동하는 링크를 배치하여, 인증 흐름의 대안을 함께 제공한다.

화면 캡처 삽입 위치: 로그인 메인 화면, 오류 메시지 표시 상태

### 나. 회원가입 화면
회원가입 화면은 이름, 나이, 이메일, 비밀번호를 입력받아 계정을 생성하는 구조이다. 로그인 화면과 같은 시각 언어를 유지하되, 배지 색상과 안내 문구를 다르게 구성해 새 계정 생성 흐름이라는 점을 구분하였다.

필수 입력 누락, 나이 유효성, 비밀번호 길이 검증이 화면 내에서 바로 처리되며, 성공 시에도 별도 성공 박스를 통해 결과를 확인할 수 있다. 또한 서버에 회원 정보가 저장된다는 안내 문구를 정책 박스 형태로 배치해 사용자가 현재 어떤 처리를 수행하는지 이해할 수 있도록 하였다.

화면 캡처 삽입 위치: 회원가입 메인 화면, 성공 메시지 표시 상태

### 다. 홈 화면
홈 화면은 로그인 직후 사용자가 가장 먼저 마주하는 대시보드 화면이다. 이 화면의 핵심 목적은 "오늘의 상태를 짧은 시간 안에 확인하고, 바로 다음 행동으로 이어지게 하는 것"이다. 상단에는 현재 날짜를 기준으로 한 주간 활동 표시가 배치되고, 중앙에는 칼로리 중심의 원형 차트와 운동/섭취 요약 정보가 배치된다.

또한 즐겨찾기 또는 추천 성격의 댄스 클래스 카드가 시각적으로 강조되어 노출되며, 사용자는 카드 터치만으로 상세 정보 확인 또는 연습 시작으로 이동할 수 있다. 홈 화면은 데이터 요약과 콘텐츠 추천을 동시에 제공하는 구조이기 때문에, 정보 밀도가 높지만 각 정보 단위를 카드와 배지로 분리해 읽기 쉽게 구성하였다.

화면 캡처 삽입 위치: 홈 메인 화면, 주간 활동 영역, 추천 클래스 카드

### 라. 클래스 탐색 화면
클래스 화면은 사용자가 댄스 운동 콘텐츠를 탐색하는 전용 화면이다. 상단에는 검색창을 배치해 원하는 클래스 이름을 바로 찾을 수 있게 하였고, 서버 연결 상태에 따라 로딩 배너 또는 대체 데이터 사용 배너를 노출한다.

화면 구성은 크게 추천 영역과 전체 목록 영역으로 나뉜다. 추천 영역에는 대표 클래스 한 개를 Spotlight 카드 형태로 크게 보여주고, 그 아래에 보조 추천 카드를 2개 배치한다. Spotlight 카드는 배경 이미지, 출처, 제목, 설명, 메타 정보, 행동 버튼까지 한 번에 담아 시각적인 몰입감을 높인다. 전체 목록 영역에서는 리스트 카드로 다양한 클래스를 나열해 탐색성을 높였다.

검색 결과가 없을 경우에는 별도 빈 상태 화면을 노출해 사용자가 현재 상태를 이해하고 다시 검색할 수 있도록 한다. 이 화면은 단순 목록이 아니라 "추천, 비교, 선택"의 흐름이 자연스럽게 이어지는 탐색 화면으로 설계되어 있다.

화면 캡처 삽입 위치: 클래스 메인 화면, Spotlight 카드, 전체 목록 카드

### 마. 클래스 상세 모달
클래스 목록에서 특정 항목을 선택하면 바텀 시트형 상세 모달이 열린다. 이 모달은 새로운 화면으로 넘어가지 않고 현재 탐색 흐름 위에서 콘텐츠 정보를 확장해 보여주는 역할을 한다.

상단 히어로 영역에는 클래스 썸네일 또는 컬러 기반 배경을 크게 배치하고, 즐겨찾기 버튼과 닫기 버튼을 함께 제공한다. 그 아래에는 출처, 제목, 부제목, 빠른 통계 정보가 배치되며, 이어서 상세 설명과 추가 정보 카드가 정리된다. 하단 액션 영역에서는 즐겨찾기 저장과 연습 시작 버튼을 동시에 제공해 정보 확인 이후 바로 행동으로 이어지도록 한다.

이 구조는 사용자가 목록 탐색 흐름을 잃지 않으면서도 개별 콘텐츠를 깊게 확인할 수 있도록 돕는다.

화면 캡처 삽입 위치: 클래스 상세 모달 상단 히어로, 하단 액션 영역

### 바. 실시간 댄스 연습 모달
실시간 연습 모달은 본 프로젝트 UI에서 가장 기능 밀도가 높은 화면이다. 사용자가 클래스 상세 모달에서 연습 시작을 누르면 전체 화면형 모달이 열리고, 여기서 카메라 기반 연습과 참고 영상 재생이 결합된다.

이 화면은 준비, 카운트다운, 재생 중, 일시정지의 여러 상태를 가진다. 상단에는 현재 클래스 정보와 상태 표시가 배치되고, 중앙에는 유튜브 참고 영상 또는 정적 프리뷰가 표시된다. 동시에 카메라 영역은 사용자의 움직임을 수집하는 입력 창으로 동작한다. 하단에는 운동 시간, 칼로리, 프레임 전송 관련 지표 등 실시간 메트릭 카드가 배치되어 현재 수행 상태를 바로 파악할 수 있게 한다.

즉 이 모달은 단순 영상 재생 화면이 아니라, 참고 콘텐츠와 사용자 입력, 실시간 분석 피드백이 동시에 결합된 인터랙티브 운동 화면이다. 사용자는 준비 단계에서 부담 없이 진입하고, 카운트다운 이후 자연스럽게 운동을 시작할 수 있다.

화면 캡처 삽입 위치: 준비 상태 화면, 카운트다운 상태, 연습 진행 상태

### 사. 음식 촬영 및 분석 화면
음식 화면은 카메라 또는 갤러리에서 음식 사진을 준비하고, 이를 서버에 업로드해 칼로리 분석 결과를 확인하는 흐름으로 구성된다. 상단에는 화면 제목과 간단한 기능 설명을 두고, 중앙의 큰 카드 영역은 이미지가 없을 때와 준비되었을 때 상태가 분명히 다르게 보이도록 설계하였다.

초기 상태에서는 카메라 촬영과 갤러리 선택 버튼을 동시에 제공해 입력 진입 장벽을 낮춘다. 사진이 준비되면 미리보기 이미지 위에 준비 완료 배지를 띄우고, 하단 행동 영역에서 사진 변경과 분석 실행 버튼을 제공한다. 분석 결과가 도착하면 총 칼로리 배지, 분석 출처, 분석 시각, 음식별 칼로리 목록을 카드형으로 정리해 보여준다.

결과가 비어 있거나 오류가 발생한 경우에도 별도 안내 카드를 통해 현재 상태를 명확히 전달한다. 따라서 이 화면은 입력, 업로드, 결과 확인의 3단계를 시각적으로 뚜렷하게 나누는 UI라고 볼 수 있다.

화면 캡처 삽입 위치: 음식 사진 준비 화면, 분석 버튼 활성화 상태, 결과 카드 화면

### 아. 기록 화면
기록 화면은 월간 운동 기록과 체중 변화 기록을 한 화면 안에서 전환해 보는 구조이다. 상단 탭 전환을 통해 월간 기록과 체중 기록 모드를 바꿀 수 있고, 각 모드는 서로 다른 시각화 방식을 사용한다.

월간 기록 모드에서는 주차별 운동 칼로리를 막대 차트로 보여주고, 월간 통계 카드와 운동 세션 목록, 달력 기반 활동 표시를 함께 제공한다. 이를 통해 사용자는 이번 달에 어느 시점에 운동이 집중되었는지, 어떤 세션을 수행했는지, 날짜별 활동 패턴이 어떤지 한눈에 볼 수 있다.

체중 기록 모드에서는 최근 여러 달의 체중 변화를 선형 흐름으로 보여주고, 목표 체중과의 차이, 평균 변화량, 가장 큰 변화 구간 등을 카드로 요약한다. 기록 화면의 핵심은 단순 숫자 나열이 아니라 "변화의 흐름"을 읽게 만드는 데 있다.

화면 캡처 삽입 위치: 월간 기록 차트 화면, 달력 기반 기록 화면, 체중 변화 화면

### 자. 프로필 화면
프로필 화면은 사용자의 개인 정보, 신체 정보, 목표 설정, 누적 성과를 관리하는 화면이다. 상단에는 아바타 형태의 이니셜, 사용자 이름, 연속 기록 수치 등을 배치해 개인 대시보드 느낌을 주고, 중간에는 키, 현재 체중, 목표 체중, 목표 기간 등의 정보를 카드형으로 표시한다.

또한 성취 배지 영역을 통해 운동 지속과 누적 성과를 시각적으로 보여주며, 하단에는 신체 정보 수정, 로그아웃 등 행동 항목을 리스트 형태로 정리하였다. 신체 정보 수정은 별도 모달에서 이루어지며, 현재 값 확인과 수정 후 저장 흐름이 자연스럽게 이어진다.

이 화면은 설정 화면에 머무르지 않고, 사용자의 목표와 누적 결과를 함께 보여주는 동기 부여형 프로필 화면으로 설계되어 있다.

화면 캡처 삽입 위치: 프로필 메인 화면, 신체 정보 수정 모달

## 4. 화면 처리 흐름

### 가. 인증 흐름
사용자는 로그인 또는 회원가입 화면에서 정보를 입력하고 인증을 수행한다. 성공 시 사용자 식별값이 저장되고, 메인 탭 구조로 이동한다. 이후 홈, 기록, 프로필 등의 화면은 이 사용자 식별값을 기준으로 서버 데이터를 조회한다.

### 나. 클래스 탐색 및 연습 흐름
사용자는 클래스 화면 또는 홈 화면의 추천 카드에서 댄스 클래스를 선택한다. 선택 직후 상세 모달이 열리고, 여기서 즐겨찾기 저장 또는 연습 시작이 가능하다. 연습을 시작하면 전체 화면형 실시간 연습 모달이 열리며, 사용자는 준비, 카운트다운, 재생, 일시정지 흐름 안에서 운동을 수행한다.

이 흐름은 탐색, 정보 확인, 실행이 자연스럽게 연결되도록 설계된 것이 특징이다.

### 다. 음식 분석 흐름
사용자는 음식 화면에서 카메라 촬영 또는 갤러리 선택을 통해 이미지를 준비한다. 이후 분석 버튼을 누르면 서버 업로드와 분석이 진행되고, 결과 카드가 같은 화면 아래에 이어서 표시된다. 즉 입력 화면과 결과 확인 화면이 분리되지 않고, 하나의 연속된 흐름으로 제공된다.

### 라. 기록 및 프로필 확인 흐름
기록 화면은 운동 결과와 체중 변화를 시간 흐름 기준으로 정리해 보여주고, 프로필 화면은 현재 신체 정보와 목표를 중심으로 사용자 개인 상태를 재정리한다. 이 두 화면은 앱 사용의 결과를 다시 확인하는 피드백 구간으로 기능한다.

## 5. UI 설계 의의
현재 모바일 UI는 기능을 단순히 나열하는 방식이 아니라, 사용자의 운동 루틴 흐름에 맞춰 각 화면의 역할을 분리한 구조를 가진다. 홈은 상태 확인, 클래스는 운동 선택, 연습 모달은 실제 수행, 음식 화면은 식단 입력, 기록 화면은 결과 확인, 프로필 화면은 목표 관리라는 식으로 각 화면이 분명한 역할을 가진다.

또한 다크 테마 기반의 카드형 UI, 강조색 분리, 바텀 시트와 전체 화면 모달의 혼합 사용은 앱 전반에 일관된 시각 언어를 형성한다. 특히 클래스 상세 모달과 실시간 연습 모달은 탐색과 실행을 끊지 않고 연결한다는 점에서 이 프로젝트 UI의 핵심적인 특징으로 볼 수 있다.

## 6. 결론
본 프로젝트의 모바일 UI는 운동 추천, 실시간 연습, 식단 기록, 변화 추적을 하나의 사용자 루틴 안에 묶어내는 방향으로 구성되어 있다. 화면 수는 많지만, 하단 탭 구조와 카드 중심의 정보 배치, 상태별 모달 흐름 덕분에 사용자는 각 기능을 비교적 자연스럽게 따라갈 수 있다.

향후 보고서 완성도를 더 높이기 위해서는 실제 앱 캡처를 각 화면별 삽입 위치에 맞춰 배치하고, 사용자 테스트를 통해 버튼 문구와 정보 밀도, 주요 카드의 우선순위를 추가로 다듬으면 된다. 그 기반이 되는 현재 UI 구조는 이미 충분히 명확하게 정리되어 있다고 볼 수 있다.
